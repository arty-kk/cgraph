# StubGraph — продуктовое описание

## 1. Краткое описание
StubGraph — это платформа для анализа исходного кода, которая строит граф файлов/зависимостей и даёт рабочее пространство для поиска, навигации, редактирования и запуска LLM‑задач поверх выбранного проекта. В составе есть API на FastAPI и фронтенд с визуальным графом, деревом файлов, встроенным редактором и панелью задач. Система поддерживает загрузку проектов из локального пути или из snapshot‑архива, индексацию (scan), построение графа, поиск (включая семантический при включённых embeddings), генерацию проектной документации и запуск LLM‑тасков (analyze/evolve/fix/impact).

## 2. Целевая аудитория и ключевая ценность
**Кому полезно**
- Разработчикам и техлидам, которым нужно быстро понять структуру большого репозитория, зависимости между файлами и «горячие» узлы кода (fan‑in/fan‑out/complexity).
- Командам, которым требуется совместная работа через организации и роли (owner/admin/member/viewer).
- Пользователям, которым нужен управляемый LLM‑поток для анализа/фикса/эволюции кода и генерации документации на основе контекста проекта.

**Ключевая ценность**
- Быстрая навигация по большому коду через граф зависимостей и богатый контекст (метрики, контракты, поиск).
- Единый интерфейс для обзора, редактирования и запуска интеллектуальных задач (LLM) прямо из UI.

## 3. Основные пользовательские сценарии
1. **Создать организацию и проект**: пользователь создаёт организацию, затем добавляет проект либо по локальному пути, либо через загрузку snapshot‑архива (zip/архив), после чего проект доступен в UI. Ограничения на локальный путь задаются настройками (allow_local_root_path).
2. **Запустить Scan и построить граф**: проект индексируется, формируются узлы и рёбра, рассчитываются метрики (complexity/fan‑in/fan‑out), после чего UI отображает граф и файлы проекта.
3. **Навигация и поиск**: пользователь ищет узлы по имени, выполняет текстовый или семантический поиск, открывает файл/узел и просматривает его контракт и метрики.
4. **Редактирование**: файл открывается во встроенном редакторе (включая diff‑режим и навигацию по зависимостям), изменения сохраняются через API с повторным индексированием и обновлением метрик графа.
5. **LLM‑задачи**: на выбранном файле запускается задача анализа/эволюции/фикса/оценки импакта; система поддерживает agentic или pack‑режим подготовки контекста, хранит историю запусков и позволяет применять патчи к файлам проекта.
6. **Генерация документации**: пользователь строит «project docs», которые формируются на основе структуры проекта и результатов индексации, и затем просматривает их в UI (Markdown).

## 4. Ключевые возможности продукта
### 4.1 Управление организациями и доступом
- Организации, роли и управление участниками через API (viewer/member/admin/owner).
- Пользовательская аутентификация, сессии и API‑ключи (login/register, revoke).

### 4.2 Управление проектами и источниками
- Создание проекта из локального пути (если разрешено настройкой) или из snapshot‑архива, хранение метаданных snapshot‑ов и ограничение их размера/количества файлов.
- Полное удаление проекта с чисткой связанных сущностей (граф, документы, embeddings, результаты задач).

### 4.3 Индексация и граф зависимостей
- Индексация проекта и построение графа зависимостей файлов, включая метрики сложности и связности (fan‑in/out).
- Локальные подграфы для выбранного файла и настройка лимитов на количество узлов/рёбер.
- UI‑визуализация графа и управление фильтрами/лейблами/фокусом.

### 4.4 Поиск
- Поиск по узлам проекта и текстовый поиск по содержимому файлов с контекстными сниппетами.
- Семантический поиск при включённых embeddings и наличии соответствующих entitlement‑лимитов.

### 4.5 Файловые операции и редактор
- Просмотр/создание/изменение/удаление/переименование файлов с пересканом и обновлением метрик графа.
- Встроенный редактор с diff‑режимом, вкладками, поиском/replace, зависимостями файла и навигацией обратно в граф.

### 4.6 LLM‑задачи и патчи
- Запуск задач (analyze/evolve/fix/impact) с гибкими параметрами контекста и режимов (agentic/pack), хранение истории запусков и применение патчей к коду.
- UI‑панель для настройки параметров задач, просмотра результатов и управления патчами/запусками.

### 4.7 Генерация документации
- Генерация Markdown‑документации по проекту (overview и расширения), хранение версии документа в БД и просмотр в UI.

## 5. Архитектура и компоненты
- **Backend**: FastAPI сервис, middleware для CORS, rate limiting и опциональной авторизации; API‑маршруты для проектов/узлов/задач/организаций/авторизации.
- **Task‑очередь**: Celery с раздельными очередями для scan/docs/run_task (heavy/medium/light).
- **Frontend**: SPA на React + Vite, основной экран — граф/редактор/панель задач, модальные окна для docs/onboarding/командной палитры.
- **Хранилище**: реляционная БД через SQLModel (PostgreSQL); ключевые сущности — Project, FileNode, FileEdge, AnalysisRun, ProjectDoc, RepoSnapshot и др.

## 6. Основные сущности и данные
- **Project**: имя проекта, корневой путь и связь с организацией.
- **FileNode / FileEdge**: узлы и связи графа (path, language, loc, fan‑in/out, complexity).
- **AnalysisRun**: история LLM‑запусков, параметры и результат выполнения/патча.
- **ProjectDoc**: Markdown‑документация проекта, сформированная системой.
- **RepoSnapshot**: метаданные загруженных snapshot‑архивов проекта.

## 7. Ограничения и важные настройки
- Локальные корневые пути могут быть запрещены через настройки, в таком случае проект создаётся только через snapshot‑архивы.
- Семантический поиск зависит от включённой поддержки embeddings и лимитов энтитлементов (например, дневные лимиты запросов/чанков).
- Применение патчей контролируется настройками (например, «только внутри контекста»).

## 8. Метрики и показатели, которые логично отслеживать
- Объём индексированных файлов и узлов графа, динамика метрик риска (complexity/fan‑in/out).
- Успешность/время выполнения задач scan/docs/LLM‑runs (через TaskJob/AnalysisRun).
- Уровень использования LLM/embeddings (OrgUsage, entitlements, лимиты).

---

**Итог:** StubGraph — это связка «граф кода + редактор + LLM‑задачи», которая превращает проект в navigable‑структуру, дополняемую интеллектуальными подсказками и инструментами, доступными через единый UI и API.
